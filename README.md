# Roulette Analyzer — настольное приложение для Windows

Настольная оболочка (Electron) вашего сайта **rouletteanalyzer.app** с активацией
по коду и привязкой к конкретному ПК.

- Интерфейс — тот же сайт, что и в браузере (обновления на Vercel подхватываются автоматически).
- Запуск только по 18-значному коду доступа; код привязывается к железу.
- Модель проверки: **онлайн-активация + офлайн-кеш** с грейс-периодом (по умолчанию 7 дней).
- Формат выдачи: **установщик `.exe`** (NSIS, с ярлыком) и **portable `.exe`** (без установки).

### Что нового в 1.1.0
- **Защита исходников:** в собранной (прод) версии полностью отключены DevTools,
  заблокированы горячие клавиши (F12, Ctrl+Shift+I/J/C, Ctrl+U) и просмотр кода.
- **Компактное окно:** минимальный размер окна уменьшен (300×380) под мини-режим
  сайта (когда виден только крупный сигнал). Пункты меню «Вид → Компактное окно /
  Обычный размер» (Ctrl+Shift+M).
- **Поверх всех окон** (always-on-top): меню «Вид → Поверх всех окон» и горячая
  клавиша **Ctrl+Shift+T**. Состояние запоминается между запусками.
- **Автообновления** (electron-updater): меню «Обновления → Проверить обновления»
  и тихая автопроверка при старте. Требует публикации релизов на GitHub Releases
  (см. Шаг 4).
- **Доменная привязка сайта:** веб-версия работает только на `rouletteanalyzer.app`
  (и локально/в preview). На чужом домене копия покажет заглушку и не запустится.
  В коде добавлен скрытый водяной знак-подпись автора.

> ⚠️ Честно про защиту: любую клиентскую защиту в принципе можно обойти
> (декомпиляция, эмуляция железа). Самый крепкий слой здесь — **серверная**
> проверка кода и привязки против вашей Supabase. Офлайн-кеш нужен только для
> удобства и ограничен по времени. 100%-й защиты не существует.

## Что уже готово

**Клиент (эта папка `roulette_desktop/`):**
- `main.js` — главный процесс Electron: проверка лицензии → сайт или экран активации.
- `preload.js` — безопасный мост (только для экрана активации; сайт к нему доступа не имеет).
- `license.js` — отпечаток ПК, активация, онлайн-перепроверка, офлайн-грейс.
- `activation.html / .css / .js` — экран ввода кода.
- `config.json` — настройки (URL сайта, эндпоинты, грейс-период).
- `build/icon.ico` — иконка приложения.

**Сервер (в проекте `roulette_vercel/`, деплоится отдельно):**
- `api/license/activate.js` — первая активация + привязка кода к устройству.
- `api/license/check.js` — периодическая онлайн-перепроверка.
- `api/admin/keys/unbind.js` — снятие привязки (перенос кода на другой ПК; только админ).
- `migration_license.sql` — миграция БД (новые поля `bound_device` и т.д.).

## Шаг 1. Развернуть серверную часть (один раз)

1. **Применить миграцию БД.** Откройте Supabase → SQL Editor и выполните
   содержимое `roulette_vercel/migration_license.sql`. Она добавляет к таблице
   `access_keys` поля `bound_device`, `bound_at`, `device_label`, `last_check_at`.
   Миграция аддитивна — существующий веб-вход не ломается.

2. **Задать секрет подписи токенов.** В проекте Vercel → Settings → Environment
   Variables добавьте переменную:
   ```
   LICENSE_SIGNING_SECRET = <длинная случайная строка, напр. 48+ символов>
   ```
   Без неё офлайн-токены будут подписываться нестабильным ключом (онлайн-проверка
   всё равно работает, но офлайн-кеш будет менее надёжным).

3. **Задеплоить** обновлённый `roulette_vercel` на Vercel (эндпоинты
   `/api/license/*` появятся автоматически — роутинг `api/**/*.js` уже настроен).

Проверка, что сервер жив (замените код на реальный):
```bash
curl -X POST https://rouletteanalyzer.app/api/license/activate \
  -H "Content-Type: application/json" \
  -d '{"key":"ВАШ_КОД_18_СИМВ","device":"testdevice123456","deviceLabel":"probe"}'
```

## Шаг 2. Собрать `.exe` на своём Windows-ПК

Сборка Windows-приложения выполняется на Windows (или потребует Wine на Linux).
На вашей машине это буквально три команды.

**Требования:** установлен [Node.js 18+](https://nodejs.org/) (LTS).

```bat
cd путь\к\roulette_desktop
npm install
npm run build
```

Готовые файлы появятся в папке `dist\` (собираются оба таргета):
```
dist\RouletteAnalyzer-1.1.0-setup.exe      ← установщик (NSIS, ярлык, автообновления)
dist\RouletteAnalyzer-1.1.0-portable.exe   ← portable (один файл, без установки)
```

> **Для автообновлений используйте установщик** (`setup.exe`): electron-updater
> корректно обновляет только NSIS-версию. Portable-версия автообновляться не
> умеет — её нужно перекачивать вручную.
>
> Если нужен только один формат — правьте `build.win.target` в `package.json`.

### Про предупреждение SmartScreen
У меня нет сертификата для цифровой подписи (code-signing), поэтому при первом
запуске Windows покажет синее окно «Windows защитила ваш компьютер». Это
нормально для неподписанных приложений. Нажмите **«Подробнее» → «Выполнить в
любом случае»**. Чтобы убрать предупреждение навсегда — нужен платный
code-signing сертификат (EV или OV), его можно купить и добавить в конфиг позже.

## Шаг 3. Выдать коды пользователям

Коды — те же, что и на сайте (панель `/admin`):
1. Зайдите в `/admin`, создайте ключ (разовый/срочный/бессрочный) как обычно.
2. Передайте пользователю 18-значный код.
3. Пользователь запускает `.exe`, вводит код → код привязывается к его ПК.

**Перенести код на другой ПК** (пользователь сменил компьютер): вызовите
снятие привязки от имени админа:
```bash
curl -X POST https://rouletteanalyzer.app/api/admin/keys/unbind \
  -H "Content-Type: application/json" \
  -b "__session=ВАШ_АДМИН_КУКИ" \
  -d '{"key":"КОД_18_СИМВ"}'
```
После этого код снова свободен и привяжется к новому ПК при следующей активации.
(Панель `/admin` уже отдаёт поля привязки `bound_device` / `device_label` /
`bound_at` в списке ключей — при желании можно добавить кнопку «Отвязать» в UI.)

## Шаг 4. Автообновления через GitHub Releases

Приложение уже умеет проверять и ставить обновления (`electron-updater`).
FeedURL берётся автоматически из `package.json → build.publish`
(`mrjonnybobby/roulette-analyzer-desktop`) — отдельно ничего прописывать не нужно.

Чтобы автообновления заработали, релизы нужно выкладывать на GitHub Releases.
Ниже — два способа. Рекомендуется первый (автоматический).

### Способ A. Автоматически через GitHub Actions (рекомендуется)

В проекте уже лежит готовый workflow `.github/workflows/release.yml`.
Он сам собирает Windows-установщик на серверах GitHub и публикует его в Releases.
Один раз настраиваете — дальше выпуск версии в одну команду.

Первичная настройка (один раз):

1. Зарегистрируйтесь на https://github.com под именем `mrjonnybobby`.
2. Создайте **публичный** репозиторий с именем `roulette-analyzer-desktop`.
3. Загрузите в него содержимое этого проекта. Из папки проекта:
   ```bat
   git init
   git add .
   git commit -m "Roulette Analyzer 1.1.0"
   git branch -M main
   git remote add origin https://github.com/mrjonnybobby/roulette-analyzer-desktop.git
   git push -u origin main
   ```

Выпуск новой версии (каждый раз):

1. Поднимите номер в `package.json → version` (например, `1.1.0` → `1.1.1`).
2. Закоммитьте и поставьте тег с буквой `v` в начале — он должен совпадать с версией:
   ```bat
   git add package.json
   git commit -m "v1.1.1"
   git tag v1.1.1
   git push origin main --tags
   ```
3. Всё. Пуш тега `v*` запускает workflow: GitHub соберёт `setup.exe`,
   `latest.yml` и блок-мапы и создаст релиз автоматически.
   Прогресс виден во вкладке **Actions** репозитория (сборка ~5–10 минут).

> Токен создавать не нужно — Actions использует встроенный `GITHUB_TOKEN`.

### Способ B. Вручную со своего ПК (запасной)

Если не хотите пользоваться Actions, соберите и опубликуйте релиз локально.
Понадобится Personal Access Token с правом `repo`
(GitHub → Settings → Developer settings → Personal access tokens):

```bat
set GH_TOKEN=<ваш_personal_access_token>
npm install
npm run publish
```

Это соберёт `setup.exe` + `latest.yml` и зальёт их в новый релиз на GitHub.

### Как обновление доходит до пользователя

Установленное приложение при старте (тихо) и по кнопке «Обновления →
Проверить обновления» читает `latest.yml` из последнего релиза, сравнивает
версии и, если есть новее — скачивает и предлагает установить.

> **Важно:** автообновляется только версия из установщика (`setup.exe`, NSIS).
> Portable-версия обновления не подтягивает.

> Пока репозиторий/релиз не настроены, кнопка «Проверить обновления» просто
> сообщит, что обновлений нет — приложение продолжит работать. Автопроверка
> при старте тихая и не мешает.

## Как это работает (поток запуска)

```
Запуск .exe
   │
   ├─ есть валидный кеш лицензии для этого ПК?
   │      ├─ да, пора перепроверить онлайн → /api/license/check
   │      │        ├─ ок           → открыть сайт
   │      │        ├─ отозван      → экран активации
   │      │        └─ нет сети     → работать по кешу, если не истёк грейс (7 дней)
   │      └─ да, проверять ещё рано → открыть сайт
   │
   └─ нет кеша / чужой ПК / истёк → экран активации
            └─ ввод кода → /api/license/activate
                   ├─ код свободен       → привязать к этому ПК, открыть сайт
                   ├─ код на другом ПК   → «device_mismatch»
                   └─ отозван/истёк      → соответствующая ошибка
```

### Отпечаток ПК
`license.js` формирует стабильный `deviceId` (SHA-256, 32 симв.) из: имени
машины, платформы, архитектуры, модели и числа ядер CPU, первого физического
MAC-адреса. При переносе кеша на другой ПК отпечаток не совпадёт → потребуется
повторная активация.

## Настройка (`config.json`)

| Поле                | Значение по умолчанию                          | Описание                                             |
|---------------------|------------------------------------------------|------------------------------------------------------|
| `appUrl`            | `https://rouletteanalyzer.app`                 | Какой сайт открывать в приложении.                   |
| `activateEndpoint`  | `.../api/license/activate`                     | Эндпоинт активации.                                  |
| `checkEndpoint`     | `.../api/license/check`                        | Эндпоинт перепроверки.                               |
| `offlineGraceDays`  | `7`                                            | Сколько дней работать офлайн между онлайн-проверками. |
| `recheckEveryHours` | `24`                                           | Как часто пытаться перепроверить лицензию онлайн.    |

## Ограничения и честные оговорки

- **Живые данные казино** (CasinoScores / livecasinodata) требуют интернета —
  как и в веб-версии. Полностью офлайн работать не будет.
- **Клиентская защита обходима.** Отключение DevTools, блок хоткеев и доменная
  привязка поднимают планку, но не дают абсолютной защиты: браузер/Electron всё
  равно получают HTML/CSS/JS. Настоящая крепость — серверная привязка кода к ПК
  (Supabase) + лицензии на Vercel: без бэкенда любая копия бесполезна.
- **Автообновление portable-версии не работает** — только установщик (NSIS).
- **Без code-signing** будет предупреждение SmartScreen (см. Шаг 2).
- **Ответственная игра:** рулетка имеет отрицательное матожидание, каждый спин
  независим, преимущество казино ≈ 2,7% (европейская). Приложение — аналитика,
  не гарантия выигрыша. См. [Wizard of Odds](https://wizardofodds.com/games/roulette/).
